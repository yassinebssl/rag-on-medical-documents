\subsection{Evaluation protocol and the daily quota}

OpenRouter allows this account 50 free-model requests per UTC day. One model with the judge on the original 30 questions needs at most 170 requests with the reply cache (210 without), so a full run takes several days. The evaluation is built around this:
\begin{itemize}
\item \textbf{Reply cache.} Every call, answers and judge, is keyed by the SHA-256 of model, prompt and token budget, and an identical request is sent once. \code{rag_hybrid} and \code{rag_rerank} retrieve the same passages, so when both gates pass, the second reuses the first one's answer and judge reply, and the two differ only by their gate.
\item \textbf{Resumable runs.} Each answer is appended to \code{results/records.jsonl} and a rerun skips it; a failed call writes nothing and is retried later. At the daily limit the run stops, writes the summary so far, and resumes on a later day.
\item \textbf{Daily job.} \code{scripts/run_evaluation.py} checks how many requests are left (which uses none), runs the five systems on the default model with the judge, then \code{rag_rerank} on the second model, and logs to \code{results/logs/}.
\end{itemize}
The plan has 240 answers: 5 systems $\times$ 40 questions on the default model, and 40 on the second model. On the first day, 2026-11-15, the job started with 47 requests left, recorded 85 answers (40 for \code{rag_hybrid}, 39 for \code{rag_rerank}, whose call for A19 failed, and 6 for \code{no_rag}), and stopped at the quota with 155 answers to go. \TODO{date on which the evaluation finished, and the number of days it took}

The retrieval comparison and the sweep make no model call; both were run on the original 30 questions, before the held-out questions existed.

\subsection{Hardware and software}

Everything runs on a laptop CPU with no GPU: the machine that runs the evaluation has an Intel Core i5-8365U (8 threads) and 15~GiB of RAM. Colab was not needed. The software is Python~3.12 with PyTorch 2.15.0 (CPU build), sentence-transformers 6.3.0, chromadb 1.5.9, pypdf 7.1.0, cryptography 50.0.2, Gradio 6.32.0 and pytest 9.2.0, all pinned in \code{requirements.txt}. The tests use fakes for every model and the database, and run offline.

\paragraph{Reproducibility.} Retrieval and the gates are deterministic for a given index. The model calls use temperature 0, but a hosted free model is not guaranteed to be deterministic: the same request for A19 gave two different outcomes (Section~\ref{sec:errors}). The reported numbers therefore come from the stored replies, which the cache keeps. A PubMed text fetched later may differ if Europe PMC updated the article; \code{check_eval_set.py} checks that the evidence quotes are still found.
